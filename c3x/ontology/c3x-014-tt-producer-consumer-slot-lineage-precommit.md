## Source-verified technical object
Official Stockfish16 `sf_16` commit `68e1e9b3811e16cad014b590d7443b9063b3eb52`, C++ `src/tt.h` and `src/tt.cpp`. A TT entry occupies **10 bytes** and retains only **16 low bits of the position key**, while cluster location is `mul_hi64(key,clusterCount)`. Cluster size **3 entries**, each 32-byte cluster with 2-byte padding. `TranspositionTable::probe` checks a 16-bit key, refreshes the generation and returns a hit on nonzero depth, otherwise chooses an empty/replacement slot with depth and generation age. `TTEntry::save` may overwrite move16 independently; depth/value/key/bound/eval overwrite occurs under exact bound, unequal low16 key, or newer/deeper depth test. The TT has no stored full 64-bit Zobrist key. Thus **observed full-key provenance must be maintained in side-car instrumentation**, not inferred from the native TT hit. A cached position key's lower 16-bit comparison alone does not certify full-key identity, although the cluster index adds a strong search-index constraint. Source comments explicitly warn save is non-atomic and can race; experiment MUST run Threads=1. The source has main and qsearch TT probes, TT static-eval accesses and all TTEntry::save callers; partial patch must not be described as comprehensive if any writer class untagged.

A *different* root world is not the *same exact TT event* even if pawn concept contrast is preserved. Put the result in source-game grouped receipt and avoid asymptotic significance claims from 28 nested worlds. Secondary: within-source world compare first-return-block incident with root output differences and downstream LMR/history/move ordering/NNUE-evaluate/alpha-beta counter changes; these are **downstream correlated path variables**, not factorial independent effects.

Important distinction: a mapping from latest physical slot writer to consumed TT entry can be authentic storage lineage *when exactly matched*; this still does not prove that particular entry's value was created by a semantic chess concept, that writer is the original underlying cause, or that the original program would visit the same nodes after ONE_MAIN. A provenance entry only certifies last save call, not entire causal ancestry of the transposition value.
