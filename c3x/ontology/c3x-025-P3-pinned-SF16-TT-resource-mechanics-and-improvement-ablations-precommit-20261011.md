## Source statements to independently verify by unmodified original source SHA
1. `TTEntry` compact slot, 16-bit key fragment `key16`, depth, generation+bound packed, stored move, score and static evaluation. A compact key match is not by itself proof of a complete 64-bit writer identity — C3X uses independent shadow writer epoch and full source key.
2. `TranspositionTable` has **3 entries per cluster**, generation increments between searches, replacement ranks **depth adjusted by generation age**. A replacement-slot candidate can be a collision or a valid predecessor in shared table.
3. **Critical subtlety:** the pinned `TranspositionTable::probe` touches `genBound8` **by refreshing generation on an entry considered matched *or empty*** before returning `found`. Thus a probe can affect future eviction priority and history even when the sought stored score is not subsequently used. A TT-FIRST intervention is not equivalent to deleting all TT read-state and cannot be interpreted purely as numeric value suppression without observing resource/age effects.
4. Same-key `TTEntry::save` preserves existing ttMove when no new move supplied; exact bound can overwrite in priority; incoming depth and PV affect overwriting. Source semantics should be version-gated before proposing a replacement heuristic.
5. Root search `ttMove`, actual `ttValue` conversion (mate/rule50), non-PV early cutoff bound/depth conditions, static eval and move-order use are separate from mere `TT.probe`. A witnessed native SEE pruning `see_ge` call is another separate path and should not be attributed to TT without E1→E2→E3→E4 chronological exact-state evidence.
