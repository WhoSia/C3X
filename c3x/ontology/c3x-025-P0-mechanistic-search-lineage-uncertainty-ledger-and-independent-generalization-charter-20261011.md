### 1. The root question is not merely which move flips
A searched root leader at depth `d` is not a persistent object: aspiration-window retries, PVS re-searches, competing root moves, alpha/beta bounds, history-sensitive prunings, and replacements can change the final return. Two correlated depths are not independent causal witnesses. Define a search episode by **an actually ordered source-native event history**, not a bag of depth leader votes.

**Noninterchangeable observables**:
1. `E0 TT_PHYSICAL_WRITER_READER`: SHA-certified writer epoch, slot and key, exact physical first read; proof of contact **not** proof of numeric TT value use.
2. `E1 TT_SEMANTIC_CONSUMPTION`: actual native stored value/bound depth/ttMove read and a specific *used* purpose: move ordering, static eval, bound cutoff, score cutoff, extension, or no use. A probe hit is insufficient.
3. `E2 COMPUTATIONAL_STATE`: same native chess node key + parent + ancestor path **AND** native move, ply, search depth, alpha, beta, PV/cutNode, rule50, TT generation/age/bound/entry-depth, root iteration and retry. Same FEN alone `STATE_MISMATCH`.
4. `E3 SEE_SOURCE_ACTIVATION`: whether exact `see_ge` is called, original move, threshold, occupied bitboard initialisation, native Boolean, parent caller site and branch consuming Boolean. Equal complete inputs imply deterministic SEE result; different *calls/states* may mediate.
5. `E4 BRANCH_ADMISSION`: observed continue/prune/LMR/extension, descendant entry and return, not just a changed token in the source log.
6. `E5 ANCESTOR_RETURN`: physically certified child value return into the parent, parent candidate update and bounded unique ancestry back toward the root. Partial histories are HOLD, not a pass.
7. `E6 ROOT_COMPETITION`: terminal root candidate score/bound, full depth, window retry, PV and other contender's score, final bestmove UCI. Reached root ≠ winner.
8. `E7 PROSPECTIVE_DECISION`: source-unseen original fixed cohort, human-literal six-field UCI model preFIRST, real native contact and source-game/event-adjusted prediction loss.

**Causal question:** `do(TT_FIRST=block)` alters E1? If yes, does the altered E1 change the exact-state E2 frontier, lead to a *new/missing* E3 SEE activation, flip an E4 branch, survive E5 return, and influence the E6 competitive final root bestmove? Require chronological native event serial `TT reader < TT semantic use < branch divergence < SEE event < ancestor/root`; if SEE is not involved, report `TT_NON_SEE_DIRECT_OR_OTHER_MEDIATOR` instead of fabricating a SEE path. Natural TT→SEE pathway can arise via node visitation, threshold, occupied, move, or prune action; identical complete SEE tuple cannot naturally flip its deterministic Boolean merely from TT blocking. For root flips without any certified E3/E5, label `MEDIATOR_UNIDENTIFIED`.

### 2. Falsifiable rival hypotheses, not ad hoc M4 repair
- H-TT-ORDER: writer→reader alters TT move ordering, not numeric cutoff; predicted downstream search order diverges before SEE with same original board; falsify by verified equal ordering plus first divergence elsewhere.
- H-TT-BOUND: TT bound/depth/value used for early return, eval, or cut changes search ancestry; falsify when no source-native bound consumed.
- H-STATE-SEE: a genuine TT-driven change in descendant visit, SEE argument or consuming branch helps mediate a root candidate. Requires unique post-first shared exact-state node + temporal source proof. If no matched computational state, identification fails (not falsification of entire pathway).
- H-ROOT-COMPETE: current-order multi-depth candidate was transient despite persistence because a later/root competing candidate or aspiration retry won. Falsify if full root competing scores and retries certified otherwise.
