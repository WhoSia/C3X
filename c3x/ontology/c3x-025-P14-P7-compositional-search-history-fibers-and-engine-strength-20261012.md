## 1. Two genuine validity barriers in the original TT

**Barrier A — full identity.** Original `tt.h` stores `key16` (low 16 bits) and uses a TT cluster index from `mul_hi64(key,clusterCount)`, cluster size 32 bytes and three entries. For Hash=16 MiB `clusterCount=524288=2^19`, and `mul_hi64(key,2^19)=key>>45`. It follows that the same index and low16 tag can occur for distinct 64-bit keys with different middle 29 bits. The source checks the short tag, not full board identity. [C++17 source abstraction court](https://github.com/WhoSia/C3X/blob/main/tools/c3x_025_P14_P7_TT_composition_and_alias_court.cpp) constructed **1,023 distinct abstract whole-key aliases** to one key while keeping index/tag fixed. These are **constructed bit patterns**, NOT proved Zobrist hashes of legal chess positions and NOT observed real collision frequency. Do not call this an experimentally witnessed TT corruption.

**Barrier B — context and draw/history.** The original `Position::key()` *does* incorporate **bucketed** rule50 information, correcting the failed initial hypothesis, but does not encode the full exact counter or repetition path. `Position::is_draw(ply)` reads the exact halfmove counter and repetition and search/qsearch checks draw before TT probing. Consequently the same full adjusted key need not determine search behavior; keyed equivalence is not a general behavioral quotient.

**Original-native experiment, not an abstract simulation:** [actual unmodified original SF16 run #38209111244 SUCCESS](https://github.com/WhoSia/C3X/actions/runs/38209111244); source `5k2/8/8/8/8/8/4Q3/4K3 w - -` with identical fullmove51, different halfmove counters 94 and100. The official native UCI `d` printed the **same FULL 64-bit key `11FDCC30DF4C6A7A`** in both. With depth4 NNUE off, Threads1, Hash16, each independently launched twice cold: at 94, `e1d2`, `score cp 1873`, nodes229; at 100, `e2d1`, `score cp 0`, nodes104. The different results follow a changed legal engine context (not necessarily an erroneous TT lookup); qsearch and regular search operate under different draw checks. Same key but different selected move **falsifies action-factorization through key alone** on this real 2-state source fiber. It does not establish any illegal Stockfish bestmove, actual hash collision between different legal chess boards, or improper TT reuse.

## 2. Mathematical theorem — which refinements are necessary and which are not yet sufficient?
Let `S` be a specified set of complete deterministic engine source states and `A:S→Moves` the actual engine choice under identical depth/NNUE/Threads/hash controls. Let `π:S→O` be the observable key. A function `f:O→Moves` with `A=f◦π` exists **iff** `A` is constant on each fiber `π^{-1}(o)`. Proof: necessity by applying f to any two states of one fiber; sufficiency define f(o) by the (constant) action in any nonempty fiber. This is elementary functional factorization, not a new general pure mathematics theorem.

**Genuine original Stockfish counterexample:** The two actual native cases above have equal key π but different selected UCI. Therefore `f(key)` cannot agree with both, even on this two-element actual engine state family. To distinguish both root moves a refined observation must have ≥2 output classes, at least **one additional bit on this fiber**. The single source-relevant bit `rule50>99` splits exactly these two worlds; source-derived CEGAR [`tools/c3x_025_P14_P7_actual_source_context_cegar.mjs`](https://github.com/WhoSia/C3X/blob/main/tools/c3x_025_P14_P7_actual_source_context_cegar.mjs) independently rechecked actual original native full key, FEN board and two different actions, then certified this *finite fiber splitting*. [Read-only CI #38209305751 SUCCESS](https://github.com/WhoSia/C3X/actions/runs/38209305751).

**No global adequacy:** `(key,rule50>99)` does not recover repetition, rule50 values away from this decision boundary, TT writer/age, aspiration search stack, candidate ordering, clocks, or full chess semantics. The inferred bit is **necessary in some form for this pair**, not a universal complete-K refinement. This is a concrete counterexample-guided abstraction refinement on real engine outputs, not purely toy CEGAR; both worlds are nevertheless outcome-exposed developmental inputs.

## 3. Conditional compositional negamax and alpha–beta semantics
Assume one shared well-defined finite-search *true node utility* v, and independently proven sound intervals on every child: `v_i∈[L_i,U_i]`. Negamax sign reversal sends child bounds to parent-move `-v_i∈[-U_i,-L_i]`. Over a legal root set, `max_i(-v_i)∈[max_i(-U_i),max_i(-L_i)]`. These transformations are sound EVEN when child scores are correlated, though the resulting Cartesian abstraction can be incomplete. A **sufficient** root winner certificate w is `L_w>max_{a≠w} U_a` for consistently comparable parent score bounds; stronger relational challenger gap abstraction survives from P14-P5. With equal bounds, the implemented original tie rule (`RootMove::score`, `previousScore`, stable input order on the active sort subrange) must be included: equality in numeric true values is not a unique chess action.

[C++17 independent finite theorem/conditional score model #38209111244 SUCCESS](https://github.com/WhoSia/C3X/actions/runs/38209111244): **343** three-child true-value worlds, **1,372** child negation/root max interval checks, **7,203** beta-window checks; 3,087 cases for separately justified lower lifts and 2,205 for upper lifts. Crucially **the score intervals are explicitly *ASSUMED trusted***. Original SF16 TT `BOUND_UPPER/LOWER` records and fail-soft qsearch returns are NOT such proved intervals; without a source→semantic value correspondence the sound abstract score information is TOP `(-∞,+∞)`. The 5 abstract hidden-value counterworlds under a source-accepted UPPER numeric branch explicitly demonstrate this insufficiency.

The composition problem is therefore naturally typed: `ObservedSourceCutoff` ≠ `VerifiedSemanticBound`; passing the first kind into negamax's bound transformer without a justified conversion is a type error. A proof-carrying chess engine should make that type boundary operationally enforceable. It should not treat genuine source branch execution, P14-P6 stable root sorting or original qsearch score provenance as complete TT validity automatically.

## 5. Actual engine strength: a falsifiable statistical protocol, not imaginary Elo
[Pure Rust color-swapped paired-opening audit](https://github.com/WhoSia/C3X/blob/main/tools/c3x_025_P14_P7_strength_trial_protocol.rs), [#38209305751 PASS](https://github.com/WhoSia/C3X/actions/runs/38209305751), tests only **4 SYNTHETIC PAIRS**, validates candidate scores 0/½/1, exactly one candidate-as-white and one candidate-as-black per opening ID, and rejects duplicate color, mismatched opening, illegal score and missing color. It computes one score per pair `X_i=(white_points+black_points)/2 ∈[0,1]`, not two independent game observations. Under independently sampled bounded opening-pair outcomes, a two-sided Hoeffding 95% deviation bound has `ε=sqrt(ln(40)/(2n))`; for **4 synthetic pairs** `ε≈0.679`, correctly illustrating negligible statistical power. Opening clustering, repeat use and engine time drift can violate the pair-independence assumption. **No true games were played, no Elo was estimated**.

An actionable production program requires (1) a genuine developed chess search policy beyond a disabled certification gate; (2) original NNUE weights and legal-chess/mate/50move/repetition/ep/tablebase regressions; (3) hardware-matched wall-clock/knps/node distributions with controlled threads/hash/time; (4) Git-human-preregistered independent opening suite and opponent settings, exact color-swapped pair IDs, all games retained; (5) sufficient power or predeclared SPRT stop rule, rating change and uncertainty, and no leakage from exposed M6 #28/July source. Do not interpret the synthetic protocol as measured chess strength or Elo.
