# C3X 0.7.0-G9.5-P3 — Causal-Field Failure Decomposition and Topology-Aware Reconstitution

## 1. Explanandum lock

P2 did not fail because its discovery field was poorly fit. It failed in the stronger place that matters: a prospectively minimal, target-blind scoped field that perfectly separated 192 discovery probes produced eight contradictions and one mixed context cell on new positions.

P3 asks: Which kind of pre-intervention structure must be represented for an exact TT-use fiber's ROOT_CHANGE law to transport beyond the contexts on which it was discovered?

The P2 contradictions are development-only failure witnesses. They may motivate schema families and test diagnostic tooling, but they have zero confirmatory authority in P3.

## 2. No cardinality race

P3 does not enumerate arbitrary supersets of the P2 basis until one passes. Instead, it freezes five semantically distinct context-schema families before fresh P3 outcomes:

1. P2_BASE — parent search depth, exact-signature occurrence, trace quartile.
2. TT_LOCAL — P2_BASE plus event window relation, bound class, payload sign.
3. TEMPORAL_LOCAL — P2_BASE plus preceding class, gap to previous same-class use, and previous→current ply transition.
4. KEY_REUSE_TOPOLOGY — P2_BASE plus equality-derived TT-key reuse degree, gap to previous same-key use, and scope transition.
5. MINIMAL_HYBRID — P2_BASE plus previous same-class gap, same-key reuse degree, and window relation.

Raw full keys, FEN, position hashes, engine names and exact event addresses are forbidden as primary context. Key equality relations may be used because they are pre-intervention relational structure and do not expose identity.

## 3. Fresh authority split

P3 uses a new source split from the same pinned Stockfish Books commit: fresh reconstitution uses 6mvs_+90_+99.epd; held-out regime uses 8mvs_big_+80_+109.epd. All P1/P2 position hashes are excluded. Positions are selected outcome-blind by SHA-256(FEN). Both arms use Stockfish 19, Berserk and Ethereal under the inherited P2 execution envelope.

The fresh discovery arm, not P2, selects the primary schema. Held-out profiles are generated separately from target packets, and target-blind scope is sealed before target opening.

## 4. Fresh schema selection

For each frozen schema family define K_s(r) = (F0(r), C_s(r)). A schema is discovery-admissible only when ROOT_CHANGE collisions = 0, compression >= 0.15, at least 24 records lie in cells spanning two or more discovery positions, at least 12 records lie in cells spanning two or more engines, and both target labels occur.

Support court requires >=96 fired records, >=2 ROOT_CHANGE=true, and >=24 ROOT_CHANGE=false.

Selection is deterministic: minimum number of coordinates added beyond P2_BASE, then frozen family rank, then lexical schema id. Fixed rank: P2_BASE → TT_LOCAL → TEMPORAL_LOCAL → KEY_REUSE_TOPOLOGY → MINIMAL_HYBRID.

## 5. Engine-conditional geometry

The same schema-family census is computed separately for each engine. Engine-specific fields are descriptive and cannot replace the cross-engine primary field. If every engine-specific field transports prospectively while the cross-engine field fails, P3 may support an engine-conditional field family with a cross-engine gluing obstruction. Engine names remain comparison indices, not context coordinates.

## 6. Search-topology coordinates

All new coordinates are computed from the unablated parent semantic-use trace under EVENT_PREFIX_ONLY causal availability: only events at or before the candidate event may contribute. Future events, next-key relations and symmetric future-looking windows are prohibited.

Temporal-local: prev_semantic_class, same_class_prev_gap_bucket, ply_transition_bucket.

Key-reuse topology: prefix-only same_key_count_bucket, same_key_prev_gap_bucket, scope_transition_bucket. Raw keys are never written to a profile.

TT-local: event_bound_bucket plus inherited event_window_relation, event_payload_sign, and event_move_presence.

## 7. Counterexample-guided diagnosis without rescue

c3x-field-p3 diagnose may open targets only after verification. It reports contradiction clusters, mixed cells, engine distribution, nearest same-fiber field cells, and abstention versus contradiction. It cannot modify a schema, promote a coordinate, alter a threshold, or re-run selection.

## 8. Explanation-service API

P3 adds a deterministic service, not an LLM. Endpoints: GET /health; POST /v1/query; POST /v1/explain; POST /v1/diagnose. The service consumes the same profile and field schemas as the research court, and explanations are fixed-template/AST outputs grounded in certificate facts.

No model weights, prompt model or external LLM are required. A future MCP, agent or LLM narrator may call this service, but it cannot expand scientific authority or replace the deterministic certificate core.

## 9. Literature positioning

Invariant prediction motivates testing stability across environments rather than treating discovery-set fit as authority. Transportability motivates explicit source/target separation. Duarte & Solus motivate context-specific causal objects. Lee & Yannakakis provide a structural donor for hidden-state distinguishing tests. CEGAR motivates counterexample-guided bounded schema evolution. Sutter et al. motivate bounding representation/context capacity so failure remains possible. C3X P23–P26 supply the prior architecture/budget-indexed law-field lineage.

## 10. Claim ceiling

A P3 PASS may establish transport of one frozen topology-aware ROOT_CHANGE field over the new source split and execution envelope. It does not establish a unique true causal context, arbitrary-position or arbitrary-engine transport, raw TT-key identity as causal, architecture descriptors as causes, cognition, intent, or human chess concepts. Abstention remains a boundary of authority, not non-causality.

## 11. Implementation principle

The research object and product object share one contract: instrumented engine → exact-event replay → F0 fiber → pre-intervention v2 profile → frozen schema field → CERTIFIED / ABSTAIN / CONTRADICTED → deterministic explanation / diagnosis.

P3 counts as engineering success only if an external user can reproduce this path from the released toolkit without a hidden notebook, model, prompt or manual adjudication.
