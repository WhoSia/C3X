# C3X 0.30 R23 — Explainable Stockfish

The target is a stock Stockfish decision that can be read back to the exact calculation, replayed, and tested with an intervention. A useful explanation should identify (1) which engine and search state selected the move, (2) where the recorded evidence changed its preference, and (3) what that evidence means on the board. Keep the independent chess interpretation's status visible.

Build clean Stockfish 16 at `68e1e9b3811e16cad014b590d7443b9063b3eb52` and a trace-enabled build of the same source and network. The logger assigns each root attempt and completed root-child event an identifier. Preserve the event ID next to the RootMove's current and prior score. Emit provenance at UCI PV formatting and final bestmove. The evidence must join by identity, not by score, index, or nominal depth alone.

Use only the exposed R21 round 1.2 and the exposed R22 pilot round 2.3 in this development test, with full legal histories. Cross two root menus (all legal vs the exactly named two) and two budgets (fixed 24,000 nodes and depth 10). Use one thread, 16 MiB hash, MultiPV 1, full strength, default NNUE on, no tablebases. Also run a paired classical development control at 24,000 nodes. For every case compare clean, patched without logging, and patched with logging. Normalize duration and NPS only in the compared search reports. Check the exact final move and legal PV. Across fixed reports require producer IDs to resolve to the recorded attempt and to the exact emitted value at the appropriate bound. Unsupported prior-score, default, or tablebase relations must be identified explicitly.

Follow a trace-selected stopping-budget intervention if an all-legal NNUE report changes its explicit leading move during the observed 24k run. Use the first case and first transition between consecutive unbounded public observations with different leaders, in the frozen order R21 then R22. Freeze the two observed report node counts before running fresh searches that request those respective amounts plus one node. Compare each returned leader with the prior actual report, and report any mismatch. This is a stopping-budget test on an exposed position, not a TT-entry intervention or a proof of chess strength.
