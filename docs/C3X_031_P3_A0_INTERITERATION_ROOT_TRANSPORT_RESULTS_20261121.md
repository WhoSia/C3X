## Search-state implication and falsifiable next intervention

The source event produced an immediate child return change but no altered enclosing root candidate value. Yet a later iteration used a different search trajectory, eventually changing its selected move. A useful source decision-state summary must therefore preserve information **between** iterative-deepening attempts (TT cached entries/reader hits, main-history/countermove/killers, node allocation, root candidate order and last-window state), not merely the current root candidate's CP score.

A matched **source-state intervention** should use a physically reached prefix in the same complete legal game and isolate:
1. the newly written or replaced TT entry identities/readers after the attempt16 targeted event;
2. corresponding history/search-order updates, if any, that survive the attempt16→17 boundary;
3. remaining node-budget constraints and actual source work, without falsifying node counts to fake a no-treatment state.

Only a genuine **restore/sham/crossover** that returns the later root candidate contrast to the counterfactual baseline under a matched checkpoint can establish a specific necessary/sufficient mediator. Directly editing late attempt18 `f4e5` values would be a **local source-score manipulation**, not proof of the earlier TT/history causal channel.
