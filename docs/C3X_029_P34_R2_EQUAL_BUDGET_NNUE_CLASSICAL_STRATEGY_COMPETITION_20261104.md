## Actually compared, under accountable computational allocation

Each strategy requested 24,000 total engine nodes per candidate, evaluated separately with `Use NNUE=false` (classical search) and `Use NNUE=true` (NNUE search):

A. One PV from root-forced full 24,000 requested nodes; predicts 1 opponent response.
B. Minimal reply-conditional JSON: 12,000 requested nodes to select the best reply on the post-root board, 12,000 after that reply to evaluate its continuation; predicts 1 response.
C. Three-reply conditional policy: one shared MultiPV=3 search at 6,000 requested nodes on post-root board, plus 3 independently forced follow-up searches at 6,000 nodes each; predicts 3 replies. **MultiPV's shared 6,000 nodes is not triple-counted**.

Actual nodes ranged from 24,006 to 24,041 (0.025–0.171% above requested). All 8 root×mode trials (4 candidates × 2 evaluator arms) execute A/B/C; no candidate legality failures. Branch output cardinality remains deliberately unequal, so these are **not equal-quality explanation fields** just because requested engine nodes are similar. Other Python overhead and Wall-clock budgets are NOT exactly equal.

A separate adjudicator exhaustively enumerated ALL 129 legal first opponent replies across 4 candidate boards, with **40,000 requested search nodes per reply for EACH evaluator mode** (classical and NNUE), keeping original complete game history. This amounts to two sets of 129 scores generated by the SAME Stockfish engine family, not an independent model of chess truth or actual root-move causes. A single response's *regret-like missed-refutation gap* is `min(reference values over predicted reply set)-min(reference values over all legal replies)`, in root player's cp perspective. This is nonnegative by construction, **not a human explanatory accuracy or probability score**. C has three predicted replies and A/B one, which improves potential coverage even absent reasoning advantage.

## Direct empirical results — development mean missed-refutation gap (centipawns, LOWER is better)

| Method generation | Classical oracle A/PV | Classical oracle B/one JSON | Classical oracle C/three plans | NNUE oracle A/PV | NNUE oracle B/one JSON | NNUE oracle C/three plans |
|---|---:|---:|---:|---:|---:|---:|
| Classical (`Use NNUE=false`) | 20.25 | 23.75 | **14.25** | 33.50 | **13.50** | 17.25 |
| NNUE (`Use NNUE=true`) | 11.50 | 11.75 | **8.75** | **0.00** | 9.00 | 1.75 |

Every mean averages exactly four ADAPTIVE exposed candidate roots, which cluster into only TWO source games. These data cannot provide valid population inference. **No single representation dominates every evaluator-mode pairing.** Under NNUE-generated search and NNUE-sourced reference, A/PV was exact-reference-best in all four (mean 0cp), defeating richer C's 1.75cp, while under classical-generated search and classical reference C had lower gap than A or B. Classical B beat C under NNUE reference (13.50 vs 17.25). Thus the value of C conditional branch breadth depends on the estimator, its inference budget allocation and the target adjudicator.

All cp values reflect original root mover's perspective; do not subtract unmatched evaluations from different evaluator arms as though they estimate a single calibration-free quantity. On case14 `c2c3`, the NNUE reference-selected worst reply `d8d7` is ALSO the observed human game reply previously omitted from depth12 MultiPV top3; this is a **specific retrospective observation**, not a proof NNUE predicts human replies better in the population or uncovers a conceptual chess cause.

**CRUCIAL IDENTIFICATION LIMIT:** Because `Use NNUE` changes evaluations *during search*, different worst replies can arise from changed evaluation values, TT use, pruning paths, aspiration windows or search ordering. It is NOT already a demonstrated difference in the NNUE *internal learned representation*. Nor does reference agreement with same-mode predictions establish external validity: reference uses the same model family/weight and more nodes.

## The real Stockfish16 evaluator pipeline discovered in exact official pinned source

`src/evaluate.cpp`, pinned official git ref above, has:
- `Value psq = pos.psq_eg_stm();`
- `bool useClassical = !useNNUE || abs(psq) > 2048;`
- When NNUE active but `abs(psq)>2048`, actual evaluator **falls back to classical**. Verified in prior original C3X 0.14 source instrumentation, 19,842/606,141 evaluations under NNUE-enabled condition (3.273%) were routed to classical.
- In NNUE route it evaluates `NNUE::evaluate(pos, true, &nnueComplexity)`, incorporates `optimism` and `npm`, then rule50 damping `v=v*(200-pos.rule50_count())/214`. Hence final Stockfish scores are not raw neural activations, and search scores differ further from leaf evaluation.
- Official `Eval::trace` invokes classical `Evaluation<TRACE>`, prints `NNUE::trace(pos)` and explicitly reports `Classical evaluation`, `NNUE evaluation`, `Final evaluation` (white-side). This supplies a **source-native unmodified direct observation path** for evaluating the same original-history board in subsequent P34/R3.

**Prior 0.25 NNUE-R1-P10 original Drive reading**: 66 authentic source-history positions, NNUE/classical × depth18/20 × FULL/LOCKED root candidates × 2 cold repeats = 1,056 native runs; 528 paired cold repeats identical; 79/264 protocol root-choice changes occurred with original FULL winner still legal; 53/69 jointly visible such pairs strict within-protocol score-sign reversals. These historical observations point to search-operator confounding even with fixed legal candidates and are not new P34 results or NNUE concept explanations.

## Scientific interpretation and next falsifier

The first P34 paired modes show a negative result against automatically equating longer condition-specific plans with superior explanation: simple PV and JSON are highly competitive under budget control. **If the user target is a chess explanation rather than worst-response forecast, the relevant criterion must separately measure verified plan-value facts, contrast to a particular foil, and whether a human can use it to reason on novel games.** This small benchmark deliberately does NOT include those subjective/human targets.

The next concrete reverse-engineering step is to use the unmodified Stockfish16 direct UCI `eval` trace at each SAME board (original history, identical root and chosen reply) to separate classical static, raw NNUE and hybrid final eval from changes in search path. Then ask whether controlled chess-concept perturbations on matched legal boards alter those raw evaluator components; after verifying repeatability, instrument input feature indices, accumulator updates, internal NNUE activation values and only then causal interventions, avoiding mere feature-attribution storytelling.
