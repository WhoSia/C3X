# C3X 0.27 — A Source-Identified SEE Pin Counterexample and Branch-Covered Repair

2026-10-20 · Actual reverse-engineering experiment · This remains C3X 0.27, not a version promotion.

## Result
Original Stockfish16 `Position::see_ge`, pinned to `68e1e9b3811e16cad014b590d7443b9063b3eb52`, agreed with an independent Python SEE routine on 960 random fixed-seed position–move–threshold inputs and an initial 441 boundary inputs. But native branch tracing revealed **zero executions of the pinned-attacker filtering branch** in those tests. A new deliberately pinned-knight example activated that branch and produced SEVEN reproducible Boolean disagreements. The independent implementation was wrong; the original C++ oracle was not patched to accommodate it.

Actual counterexample FEN: `8/6k1/8/8/3n4/5p2/8/B4R1K w - - 0 1`; candidate `f1f3`. White's bishop on a1 pins Black's knight on d4 to the king on g7. The knight geometrically attacks f3 but cannot take the rook there without exposing its own king. Stockfish's original SEE returns TRUE for thresholds -1100, -200, -95, -43, 0, 1 and 126; the earlier independent implementation returned FALSE at exactly these seven compared thresholds. This negative finding was certified on GitHub Actions [run 39345837347](https://github.com/WhoSia/C3X/actions/runs/39345837347), artifact 12230913077, with old boundary result 495 comparisons and 7 mismatches. The preexisting 960 random tests continued to match.

## Source-exact repair
Read original `Position::slider_blockers` and `Position::set_check_info`: pin masks are not produced by a normal attack lookup of the king. The original routine identifies an aligned sliding sniper, removes sniper squares from occupancy, looks for exactly one intervening piece, and marks a sniper as a pinner when the intervening piece belongs to the king's side. The SEE routine subsequently tests whether those **original-source pinners remain occupied** and removes `blockers_for_king(stm)` from candidate attackers. The prior independent routine instead queried an ordinary attacker mask at the king and could not see a sniper screened by its pinned piece.

Added `tools/c3x_027_independent_see_v2_exact_pins.py` implementing the original pin/slider blocker geometry as an independent pure-Python function. The old implementation is retained in Git history as a falsified baseline. Neither Stockfish's `see_ge` return nor legal move generator was changed.

The corrected checker was rerun on the same fixed comparison protocol. [Run 39346219279](https://github.com/WhoSia/C3X/actions/runs/39346219279): random 960, zero mismatches; boundary 495, zero mismatches, with original-native pin filtering still activated 7 times. Thus total 1,455 executed comparisons, observed discrepancies zero. Castling 18 direct comparisons were included, not excluded.

## Scientific inference and limits
This experiment **falsified and repaired a concrete independent implementation** using a source branch that the preceding large agreement counts had missed. It does not prove mathematical bitwise equivalence over all legal positions, all thresholds, every optional occupied output, every in-check state, or every SEE control-flow path. Although the new SEE oracle returns an `occupied` bitboard, in Stockfish16 it is a reference output overwritten by the algorithm on normal moves; it is not an independently supplied starting mask. Native branch counters are per calls, not independent games, and fabricated positions do not measure downstream TT-to-SEE-to-root mediation. The fresh game-disjoint causal cohort remains to be executed.

## Replacement Results prose (Research OS WRITING 3.0)
The first differential test looked decisive: 1,401 calls to the unchanged Stockfish16 exchange routine produced no disagreement with our separate checker. The source trace told a different story. Although several examples contained pinned pieces, not one of those calls had actually removed a pinned attacker during exchange evaluation. We built a position in which a pinned knight was the apparent defender of a captured pawn. Seven threshold tests immediately separated the implementations. Stockfish rejected the pinned knight as a recapturing attacker; our first Python checker mistakenly allowed it to participate.

The cause was specific. We had approximated Stockfish's pin information with an attack lookup at the king. In the source routine, however, the sliding attacker behind a pinned piece is deliberately removed from the occupancy used to find a single blocker. Replicating that geometric step corrected all seven failures without changing the original chess engine. The final 1,455 paired tests again agreed, now with seven actual executions of the native pinned-attacker filter. We also measured newly exposed sliding attackers rather than treating every X-ray recomputation as a discovery.

The experiment is an example of why output agreement alone is not enough to reverse-engineer a search primitive. Its stronger result is a falsifiable relationship between exact source branches, deliberately chosen chess states and independent predictions. Whether these same primitives carry causal information about the engine's final move choice is the next experiment, not a conclusion of this one.
