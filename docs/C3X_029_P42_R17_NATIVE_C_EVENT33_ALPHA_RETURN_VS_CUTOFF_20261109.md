# C3X 0.29–P42/R17 — Local Alpha and Cutoff Consequence of One Actual C-World Draw Event

Date: 2026-11-09 KST. Pre-outcome registered native hypothesis and claim boundary. The research flagship is NOT a paper on easy search metrics but source causal mechanism linked to independent adversarial chess meaning.

## Established physical native background

Frozen Game14 (official Stockfish16 pinned commit, NNUE OFF, postselected) root source: B TT_FIRST f3f4; C capture-prune bypass b3a4; B33 one cycle event33 return neutralized b3a4.

R15 double source perturbation **physically** applied both C's exact guard bypass and the new combined search's 33rd cycle call, restored b3a4 twice and matched C depth9. Yet the targeted combined ordinal33 **did not** equal B's original source event33 identity. Native R16 [#42551289145](https://github.com/WhoSia/C3X/actions/runs/42551289145) followed the B original event across every actual C and combined source call. **One identical board key, ply, depth, root move, alpha and beta context exists in C and combined**, but **no** occurrence with the same node count mod4. B calls 281/source engine; C and combined 403 each. R16 crucially also confirmed that C and C+33 have **the same observed pre-score source context for all 403 events and the same 12-depth root summary**, without proving unlogged state identity.

This exposes a new factual question: R15's C+33 changes the 33rd *C-world* `value_draw` return, but is this return difference responsible for an immediate `alpha>=beta` cutoff difference? Does any subsequent *observed* cycle-alpha source context diverge? It is logically invalid to infer a cutoff or no cutoff merely from root equality.

## Predeclared R17 source test

Using the original R16 same-pinned-source execution with private raw R11 cycle traces, compare original C and C+33 for both cold repeats (with two physical subprocesses verified by R12 strict two-play parser):

- At event33 require **exact** same native position key, ply, depth, root candidate, alpha/beta window and node-mod4 pre-score context.
- Require a real C source return in `{-1, +1}` (the original `value_draw = -1+(nodes&2)`) and an actual combined event33 neutral return `0`.
- Require all other actual cycle-alpha event candidate and cutoff tuples to be unchanged and every pre-score source context in both physical C/C+33 streams to match. If dynamic support or values differ unexpectedly, HOLD. Do not silently select a later matching event.
- Compare the actual local `alpha>=beta` decision at C's own event33 under both modes. A changed local alpha is not necessarily a changed immediate cutoff or change in root ranking.
- Require old R16 source support and full R14/R15 physical controls before reporting a native result, preserving the combined C vs C+33 12-depth root summary identity check.

Output only aggregate return delta, cutoff Boolean, number of post-event source calls, and explicitly FALSE certificates for unobserved full search state, natural B-event33 mediation, source-to-root lineage and chess-strategic meaning. Never release native key, full windows, source game or modified GPL binary. Strict read-only Actions, WhoSia authors.

**Interpretable possibilities**: (i) one local alpha candidate changes but immediate cutoff remains identical and no observed root boundary moves; (ii) immediate cutoff changes despite unchanged later *logged* cycle contexts/root summary, which would demand analysis of other search state; (iii) pre-score state drift or additional return changes => HOLD, requiring a different causal matching protocol. None alone makes the source calculation a valuable chess strategy reason.
